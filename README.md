# HomeJoy — интернет-магазин мебели

Node.js + Express + SQLite (better-sqlite3), фронтенд на чистом HTML/CSS/JS.

## Запуск

```
npm install
npm start
```

Сайт откроется на http://localhost:3000. Для разработки с автоперезапуском: `npm run dev`.

## Что умеет

- Каталог из базы SQLite: 42 товара в 8 категориях, фильтры по категории и цене, поиск, сортировка, страницы по 8 товаров.
- Новые товары: допишите их в `data/products.json` и перезапустите сервер — они добавятся в базу, существующие данные не тронутся. Рисунок для товара задаётся в `images.js` (`REAL_DRAW`), настоящее фото — файлом в `images/`.
- Главная: карусель «Хиты продаж» (10 самых оценённых товаров), «Недавно смотрели» (история в браузере, блок скрыт, пока она пуста), «Как мы работаем».
- Анимация «Мастер собирает стеллаж» на главной (`assembly.js`, стили `.assembly` в `style.css`): мастер быстро перебегает между сторонами стеллажа и шуруповёртом вкручивает шурупы. Расписание задано в начале `assembly.js` (массив `SEQ`). Запускается при прокрутке, есть кнопка «Показать ещё раз»; при включённом «уменьшить движение» в системе показывается готовая сцена.
- Страница товара с отзывами и рейтингом (отзывы сохраняются в базе).
- Корзина и оформление заказа (`/checkout.html`). Цены и промокод `JOY15` (−15%) считает сервер.
- Оплата заказа: наличными, картой при получении или картой онлайн через тестовый банк-эмулятор (см. раздел «Оплата» ниже).
- Отслеживание доставки (`/track.html`) — карта с маршрутом курьера «как в Яндекс.Такси» (см. раздел «Доставка на карте» ниже).
- Конструктор комнаты на главной.
- Карточка товара: кнопки «В избранное», «Сравнить» и «Быстрый просмотр» (окно с ценой, характеристиками и кнопкой «В корзину»). Избранное (`/wishlist.html`) и сравнение до 3 товаров (`/compare.html`, можно показать только различия) хранятся в браузере; счётчики — в шапке.
- Страница товара: увеличение изображения (лупа или клик), блок «С этим покупают» (по одному товару из дополняющих категорий, ближайшему по цене; правила — `COMPLEMENTS` в `script.js`) и до четырёх «Похожих товаров».
- Загрузка без «Загрузка…»: заглушки-скелетоны, плавное появление карточек, анимация счётчика корзины (отключаются при «уменьшить движение»).
- Строгий стиль и тёмная тема: переключатель в шапке (выбор запоминается в браузере, до загрузки страницы применяется скриптом в `<head>`, поэтому без мигания). Блок тёмной темы в конце `style.css` сгенерирован из правил выше — при заметных правках цветов проверьте обе темы. Иконки — единый набор `ICONS` в `script.js` (в статичной разметке: `<span data-icon="truck"></span>`).
- SEO: мета-теги, иконка, `/robots.txt`, `/sitemap.xml`.
- **ИИ-консультант** — круглая кнопка в правом нижнем углу на всех страницах сайта (кроме админки). Отвечает на вопросы о мебели, доставке, гарантии и оформлении заказа; знает список категорий и диапазоны цен из базы, но не выдумывает конкретные модели — направляет в каталог. Модель — `gemini-3.5-flash-lite` (бесплатный уровень Gemini API), запрос идёт через сервер (`assistant-api.js`, `POST /api/assistant/chat`), ключ `GEMINI_API_KEY` браузер никогда не видит. Без ключа кнопка остаётся, но чат отвечает «временно недоступен». История разговора хранится в `sessionStorage` вкладки (не на сервере). Лимит — 20 сообщений за 10 минут с одного адреса.

## API

| Метод | Адрес | Что делает |
|---|---|---|
| GET | `/api/health` | проверка, что сервер жив |
| GET | `/api/categories` | категории с количеством товаров |
| GET | `/api/products` | каталог: `category`, `q`, `minPrice`, `maxPrice`, `sort=price_asc\|price_desc`, `page`, `limit` |
| GET | `/api/products/:id` | один товар (404, если нет) |
| GET / POST | `/api/products/:id/reviews` | список отзывов / новый отзыв `{ name, rating, text }` |
| POST | `/api/orders/quote` | расчёт заказа `{ items:[{id,qty}], delivery, promo }` |
| POST | `/api/orders` | создать заказ (плюс `name`, `phone`, `email`, `address`, `comment`, `paymentMethod`: `cash`\|`card_on_delivery`\|`card_online`). Для `card_online` в ответе приходит `payUrl` — ссылка на страницу оплаты |
| GET | `/api/orders/:id/payment-status` | статус оплаты заказа: `{ method, status }` (`status`: `unpaid`\|`paid`\|`failed`) |
| POST | `/api/orders/:id/pay-link` | новая ссылка на оплату, если первая попытка не удалась |
| GET | `/api/orders/:id/route` | маршрут доставки для `/track.html`: координаты магазина/адреса, ломаная по дорогам, статус и прогресс курьера |
| POST | `/api/payments/callback` | вебхук от MOCK-банка (сервер-сервер, с подписью) — браузер сюда не обращается |
| POST | `/api/assistant/chat` | ИИ-консультант: `{ messages: [{ role: "user"\|"assistant", text }] }` → `{ reply }` |

## Фото товаров

Положите файл в папку `images/` под именем `<id товара>.jpg` (подойдут `.png`, `.webp`) — сайт покажет его вместо рисунка.
Дополнительные фото для галереи: `<id>-2.jpg`, `<id>-3.jpg` … (до 6). Перезапуск не нужен.

## Админ-панель

Адрес: `/admin.html` (например, http://localhost:3000/admin.html). Вход по паролю, сессия на 8 часов.

- **Заказы** — список с составом и контактами, смена статуса (новый → подтверждён → отправлен → выполнен / отменён), фильтр по статусу. Для каждого заказа видно способ и статус оплаты; для наличных и карты при получении есть кнопка «Отметить оплаченным» (для карты онлайн статус меняет только банк-вебхук). Перевод заказа с доставкой курьером в статус «Отправлен» запускает отсчёт для карты маршрута на `/track.html` (см. «Доставка на карте» ниже).
- **Выгрузка для бухгалтерии** (вкладка «Заказы») — CSV, который открывается в Excel двойным щелчком. Период (или «Этот месяц», «Прошлый месяц», «За всё время») и статус заказов выбираются на странице. Два файла:
  - «Заказы» — одна строка на заказ: номер, дата, статус, покупатель, телефон, email, получение, адрес, промокод, комментарий, число позиций и штук, сумма товаров, скидка, доставка, итого;
  - «Позиции» — одна строка на товар в заказе: то же про покупателя + артикул, товар, категория, количество, цена, сумма (удобно для сводных таблиц).

  Формат: UTF-8 с BOM, разделитель `;` (как в русском Excel), даты в местном времени (`REPORT_TZ`, по умолчанию `Europe/Moscow`). Если Excel открыл всё в одну колонку (английская локаль) — «Данные → Из текста/CSV» и разделитель «точка с запятой». Тот же файл отдаёт `/api/admin/orders.csv?kind=orders|items&status=&from=ГГГГ-ММ-ДД&to=ГГГГ-ММ-ДД` (нужен вход в админку). Ячейки, начинающиеся с `=`, `+`, `-`, `@`, экранируются апострофом, чтобы чужие данные не превратились в формулу.
- **Товары** — добавление, редактирование, удаление; загрузка фото (основное и до 5 дополнительных для галереи).
  Удалённые товары не возвращаются при перезапуске сервера, даже если они есть в `data/products.json`.
- **Отзывы** — просмотр и удаление (рейтинг товара пересчитывается).

**Пароль.** При первом запуске сервер создаёт случайный пароль и один раз печатает его в консоль.
Задать свой: `npm run admin-password -- МойПароль` (от 8 символов; без аргумента — случайный).
На хостинге удобнее переменная окружения `ADMIN_PASSWORD` — она важнее пароля из базы.

**Защита.** Пароль в базе хранится в виде scrypt-хэша; cookie `HttpOnly` + `SameSite=Strict`; запросы,
меняющие данные, принимаются только со своего сайта; после 5 неверных паролей вход блокируется на 15 минут.
Страница админки закрыта от поисковиков (`noindex`, `robots.txt`). На хостинге обязательно включите HTTPS.

## Оплата

Три способа: наличными, картой при получении (оба подтверждаются вручную в админке) и картой онлайн.

Для оплаты картой онлайн сайт перенаправляет покупателя на демо-имитацию банка **MockPay**
(`mock-bank/router.js`) — оно имитирует работу банка, никаких реальных денег и реального процессинга нет.
По умолчанию MockPay встроен в тот же процесс, что и магазин, и открывается на `/bank` — отдельный
сервис поднимать не нужно, для шаринга ссылки на сайт достаточно одного адреса.

1. При оформлении заказа с «Картой онлайн» сервер магазина подписывает ссылку (`orderId`, `amount`) секретом и отдаёт её браузеру как `payUrl` (`<сайт>/bank/pay?...`); браузер переходит на страницу оплаты.
2. MockPay проверяет подпись (иначе — «ссылка повреждена или подделана»), показывает форму карты. Тестовые номера: `4242 4242 4242 4242` — успешная оплата, `4000 0000 0000 0002` — отклонённая; остальные поля — любые.
3. После «оплаты» результат применяется к заказу напрямую (внутри процесса), минуя браузер — источник истины один, подделать статус через query-параметры нельзя. Браузер отдельно редиректится на `/payment-result.html`, но это только для UI.
4. Если оплата не прошла, на `/payment-result.html` есть кнопка «Оплатить снова» (`POST /api/orders/:id/pay-link`).

MockPay можно запустить и отдельным процессом на своём порту — например, если хочется показать архитектуру
с разнесёнными сервисами: `npm run bank` (слушает `BANK_PORT`, по умолчанию `4242`), и указать магазину
`BANK_URL=http://localhost:4242`. В этом режиме результат оплаты передаётся уже не прямым вызовом, а
подписанным запросом сервер-сервер на `POST /api/payments/callback`.

Секрет для подписи — переменная окружения `PAYMENT_SECRET`, а если её нет — файл `data/payment-secret.txt`,
который сервер создаёт сам при первом запуске (в `.gitignore`, в репозиторий не попадает). Если магазин и
MockPay работают на разных хостах (раздельный режим), задайте `PAYMENT_SECRET` одинаковым для обоих явно.

| Переменная | Где | Зачем |
|---|---|---|
| `BANK_URL` | магазин | адрес MockPay, **только** если он запущен отдельным процессом (по умолчанию — свой же `/bank`) |
| `BANK_PORT` | MockPay (отдельный процесс) | порт сервера MockPay (по умолчанию `4242`) |
| `PAYMENT_SECRET` | оба | общий секрет подписи; без него каждый использует/создаёт `data/payment-secret.txt` |

## Доставка на карте

Страница `/track.html` показывает маршрут курьера на карте — в духе Яндекс.Такси: точка магазина, точка
адреса доставки и маркер курьера, который едет между ними по настоящим дорогам. Курьера на самом деле
нет — как и у MockPay, это демонстрация, а не GPS-трекинг: прогресс считается от времени, прошедшего
с момента оформления заказа, а не от реального местоположения, и запускается полностью автоматически —
никаких действий в админке не требуется. Сразу после заказа курьер «собирается» (`PREP_MS`, 20 секунд),
затем «едет» фиксированное время (`DEMO_TRIP_MS`, 15 минут) — обе константы в `delivery.js`.

Карта и маршрут — полностью бесплатные публичные сервисы без ключа и регистрации:

- **Leaflet** — библиотека карты, установлена как обычная npm-зависимость и отдаётся сервером со своего
  домена (`/vendor/leaflet/…`), ключ не нужен; тайлы карты — с `tile.openstreetmap.org` (OpenStreetMap).
- **Nominatim** (OpenStreetMap) — превращает адрес, который покупатель ввёл при оформлении заказа, в
  координаты. Запрос идёт с сервера магазина (не из браузера) и один раз кладётся в базу (`dest_lat`,
  `dest_lng`), повторно не геокодируется.
- **OSRM** (`router.project-osrm.org`) — строит маршрут по дорогам между магазином и адресом; результат
  кэшируется в памяти сервера.

Если адрес слишком неточный («Советская» без города и т. п.) и Nominatim не может его найти, страница
покажет «Не удалось определить точку на карте по адресу» — это ограничение бесплатного геокодера, а не
баг. Координаты магазина (угол ул. Лесной) заданы константой `STORE` в `delivery.js` — поменяйте, если
адрес магазина в `contacts.html` изменится.

## ИИ-консультант

Бесплатный ключ: зайдите на [aistudio.google.com](https://aistudio.google.com/) под Google-аккаунтом → «Get API key» → «Create API key».
Задайте его переменной окружения `GEMINI_API_KEY` (локально — например, в `.env`, если используете `dotenv`, или прямо в терминале перед запуском: `GEMINI_API_KEY=ваш_ключ npm start`) и перезапустите сервер.
Без ключа сайт работает как обычно, кнопка чата просто отвечает, что ассистент недоступен.

Используемая модель (`gemini-3.5-flash-lite`) и системная инструкция заданы в `assistant-api.js` — там же лимит запросов,
длина истории и правила ответа (не выдумывать конкретные товары, направлять в каталог/контакты).

## Выкладка в интернет

Нужен хостинг, где можно запустить Node.js-процесс (VPS, Render, Railway, Fly.io и т. п.).
Статический хостинг (GitHub Pages и подобные) не подойдёт: у сайта есть сервер и база данных.
MockPay (оплата картой) по умолчанию встроена в этот же процесс — отдельный сервис не нужен,
достаточно одного адреса, которым можно делиться.

### Render.com — быстрый вариант (бесплатный тариф)

1. Запушьте проект на GitHub (уже сделано, если репозиторий подключён — `git push`).
2. На [render.com](https://dashboard.render.com/) → **New** → **Web Service** → выберите этот репозиторий.
3. Настройки сервиса:
   - **Runtime**: Node
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: Free (или платный, если нужен постоянный диск — см. ниже)
4. Вкладка **Environment** → добавьте переменные:

   | Переменная | Значение |
   |---|---|
   | `GEMINI_API_KEY` | ваш ключ ИИ-консультанта |
   | `ADMIN_PASSWORD` | пароль для входа в `/admin.html` |
   | `SITE_URL` | заполнится само после первого деплоя (адрес вида `https://ваш-сайт.onrender.com`) — впишите его сюда и передеплойте, тогда ссылки в письмах/sitemap будут правильные |
   | `TRUST_PROXY` | `1` (Render — это прокси, без этого лимиты запросов будут видеть один IP на всех посетителей) |

5. **Create Web Service** — через пару минут появится публичный адрес `https://<имя>.onrender.com`, им и делитесь.

**Важная особенность бесплатного тарифа Render**: диск не постоянный — файл базы (`data/shop.db`) и папка `images/`
пересоздаются «с нуля» при каждом деплое и иногда при перезапуске простаивающего сервиса. Каталог товаров
каждый раз досеется заново (это в коде, не страшно), а вот **заказы и загруженные через админку фото между
перезапусками не сохранятся**. Для демонстрации/тестирования это обычно не проблема; если нужна настоящая
сохранность данных — на Render это платный **Persistent Disk**, подключите его и укажите:

| Переменная | Зачем |
|---|---|
| `DB_PATH` | путь к файлу базы на диске, например `/var/data/shop.db` |
| `IMAGES_DIR` | путь к папке с фото на диске, например `/var/data/images` |

### Другие варианты

То же самое работает на Railway, Fly.io или обычном VPS — отличаются только шаги подключения GitHub-репозитория
и постоянного диска в панели хостинга; переменные окружения и команды те же (`npm install`, `npm start`).

| Переменная | Зачем |
|---|---|
| `PORT` | порт сервера (большинство хостингов задают его сами) |
| `ADMIN_PASSWORD` | пароль админ-панели (иначе используется пароль из базы) |
| `DB_PATH` | путь к файлу базы на **постоянном диске**, например `/var/data/shop.db`. Без этого база пропадёт при пересоздании контейнера |
| `IMAGES_DIR` | путь к папке с фото товаров на **постоянном диске**, например `/var/data/images`. Без этого фото, загруженные через админку, пропадут при пересоздании контейнера |
| `SITE_URL` | адрес сайта, например `https://homejoy.example` — попадёт в `sitemap.xml` и в ссылку возврата из MockPay |
| `REPORT_TZ` | часовой пояс дат в CSV-выгрузках, например `Europe/Moscow` (по умолчанию так и есть) |
| `TRUST_PROXY` | `1`, если сайт стоит за прокси хостинга (иначе лимит отзывов видит один IP на всех) |
| `GEMINI_API_KEY` | ключ для ИИ-консультанта (см. раздел выше); без него чат отвечает «недоступен» |
| `BANK_URL` | адрес MockPay, **только** если он запущен отдельным процессом (см. раздел «Оплата») |
| `PAYMENT_SECRET` | общий секрет подписи; без него сервер создаёт `data/payment-secret.txt` сам |

1. Включите HTTPS (на большинстве хостингов он есть из коробки).
2. Перед запуском замените в футере и на странице «Контакты» тестовые телефон, адрес и email.
3. Делайте резервную копию файла базы и папки `images/` — в них заказы, отзывы, товары и загруженные фото.

> Важно: версия `better-sqlite3` закреплена на 12.10.1 — на новой 13.x у нас был сбой на Windows.
